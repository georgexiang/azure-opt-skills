# 项目 Case MD 导入

完成标准：`project_case_upload` 返回本次原附件的持久化导入回执。读取文件、生成总结或写入 Sandbox 文件不等于导入成功。

## 1. 定位当前项目附件

确认用户要求将附件作为本项目日报的 Case 来源。使用当前项目会话中用户实际上传的 `.md` 附件身份，不根据文件名、正文中的项目名或其他会话内容选择项目。

文件没有固定模板，可以是 Markdown 列表或包含多个 Case。处理人、状态、客户或 Case 编号缺失不要求用户补齐；日报会如实标注未知。

没有附件时请用户上传 `.md`。非 `.md` 文件说明不支持；不转换邮件、图片、PDF，不从网址下载文件，也不将助手生成的文字保存为“用户原附件”。

完成条件：已定位本次用户附件的真实 `artifactId`，或已明确说明缺少附件/格式不支持。

## 2. 调用受控导入工具

本次执行完整读取本 Skill 后，调用平台原生工具 `project_case_upload`，传入真实附件 `artifactId`。项目、上传时间、成员权限、原文读取和内容哈希由服务端核验；不自行填入这些值或传入改写后的正文。

工具负责判断是否包含 Case，并返回：

| 状态 | 行为 |
| --- | --- |
| `imported` | 已持久保存原 MD，展示回执及日报归属日期 |
| `duplicate` | 本项目同日相同内容已经导入，展示已有回执，不重复导入 |
| `rejected` | 明确说明无 Case、文件不合格或拒绝原因，不宣称保存 |
| `needs_confirmation` | 按下一节处理，尚未成为日报来源 |

接口缺失、无权限、文件不可读、超限、模型或存储失败时，保留工具返回的安全错误说明并明确失败。服务不可用时不改用 curl、个人令牌、数据库直写或 Sandbox 临时文件绕过。

完成条件：取得工具回执或明确错误，不依据自然语言猜测提交是否成功。

## 3. 仅在不确定时请求确认

若收到 `needs_confirmation`，展示文件名、服务端说明、`confirmationId`，请用户发送：

```text
确认导入 <confirmationId>
```

英文会话可发送 `confirm import <confirmationId>`。等待真实的新用户回复；助手不得替用户生成或发送确认。

用户按此格式确认后，重新完整读取本 Skill，调用 `project_case_upload` 并传入该 `confirmationId`，按照工具 schema 提供关联参数。服务器会核验当前用户、同一项目/会话、文件版本和新用户确认；过期或变更的确认应重新执行导入判断。

明确不含 Case 的文件被拒绝时，不使用确认流程强行导入。确认只授权这份原 MD 作为日报来源，不授权立即发邮件或修改 Case。

完成条件：确认后取得 `imported` / `duplicate` 回执，或说明未确认/已取消/失败。

## 4. 返回简洁结果

仅展示文件名、导入状态、回执编号、北京时间报告归属日期及必要错误。

- 同项目同日重复内容只计一次；跨日主动重传可进入新一天日报。
- 日报只汇总所属日期经本 Skill 成功导入的 MD，生成时再整理 Case 状态、处理人、进展和来源。
- 若所属日期邮件已经生成，原日期报告页可查补充材料，不补发或改写旧邮件。
- “已保存”不等于“已纳入邮件”或“已发送”；不承诺即时投递。

本 Skill 不建立逐 Case 台账，不读取全部历史工单，也不改变原项目日报的收件人、时间或发信授权。
