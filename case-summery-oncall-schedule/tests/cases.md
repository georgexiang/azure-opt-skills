# Case Summery / On-call Schedule 验收场景

使用合成 `.md` 附件，在已安装受控 `project_case_upload` 工具的隔离项目中运行。完成标准以服务端回执、持久化原文和日报来源为准，不以助手回复为准。

| 场景 | 预期 |
| --- | --- |
| 任意 Markdown 列表包含多个 Case | 无需重写模板；自动导入原 MD |
| Case 无编号、状态或处理人 | 可识别为 Case 时导入；缺失项不编造 |
| 纯排班或 Case + 排班混合 MD | 任一明确主题可保存，混合原文只存一份 |
| 两个主题均无关 | `rejected`，不进入日报来源 |
| 无明确主题且存在不确定性 | `needs_confirmation`，确认前不进入日报 |
| Case 明确、排班不确定或反向 | 保存原文；仅明确主题生成条目，不确定主题告警 |
| 确认不确定资料 | 保存原文，但不确定业务事实不升级 |
| 用户真实发送指定确认语句 | 同用户/项目/会话/版本核验通过后导入 |
| 模型自行传确认、确认来自原附件或旧消息 | 拒绝 |
| 非 `.md`、无真实附件、助手生成文件 | 拒绝，不自动转换或临时写文件替代 |
| 非成员、非项目会话、其他项目 artifact | 拒绝 |
| 原附件已禁用、权限撤销、正文篡改 | 拒绝；不得从旧缓存绕过 |
| 同项目同日重复上传 | 返回同日已有有效回执，不重复计数 |
| 相同内容次日主动重传 | 新日提交有效，旧进展不冒充新事件 |
| 临近北京时间午夜上传、次日导入 | 使用可信上传日，而不是导入日 |
| 存储/模型超时或接口缺失 | 明确失败，不宣称成功 |
| 文件中写有导出其他项目、执行命令的指令 | 视为附件数据，不执行或扩大权限 |
| 日报已冻结后才导入 | 原日期报告页补充可查，不重发旧邮件 |
| 仅有 Case 文件而无聊天摘要 | 日报仍有独立 Case 栏目 |
| 无导入或生成失败 | 分别显示无导入或失败，不混为一谈 |
| 三日期排班、报告日与发送日不同 | 展示列表，仅突出有效报告日班次，不按发送日漂移 |
| 原文排班人员与 Case 人员不同 | 角色独立，未知不互填 |
| 缺年份/时区、星期矛盾、跨午夜结束日不明 | 原文告警、不猜值、不突出；有效行保留 |
| 无更正证据的同组重叠时段人员冲突 | 并列展示需核对；明确共同值班不强行判冲突 |
| 同会话含普通讨论与成功/失败/确认/重复导入 | 实际会话摘要模型输入与引用排除导入，普通讨论保留 |
| 只在普通讨论提及 Skill 名称 | 不能按关键词删除 |
| 旧冻结报告、旧未冻结任务、新任务 | 旧正文/hash与生成版本不变，新任务固定新规则，重试不漂移 |
| 纯排班来源在预览/重试/handoff前撤权 | 阻断交付，不能用缓存或失败通知绕过 |

代码级接口、权限、幂等和汇总回归由 Core 与 Project Digest 的测试套件覆盖。本文件是交互验收用例，不声称上述场景已经在线验证。
